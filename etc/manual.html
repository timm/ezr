ezr(1)

multi-objective explanation from a few labels

Synopsis

./ezr_eg.py [-Key val]... [--demo]...

Description

Rows have x columns that are cheap and known, and y columns that are costly and mostly unknown. Reading one row's y is the only expensive act, so ezr spends as few reads as it can.

  1. Label a few rows at random; sort them by ydist.
  2. Split those into best and rest; take the two centroids.
  3. Label whichever unlabelled row looks nearest best and farthest from rest — judged on x columns only, which are free.
  4. Repeat to the budget. That loop is acquire.
  5. Grow a tree over what got labelled, splitting on whatever tightens y most. Its leaves are the explanation.

grabs does step 1 only, forever: the straw man that any real acquisition has to beat.

Data

A csv whose header row names, types and routes every column. An upper-case first letter means numeric, otherwise symbolic. The last letter gives the role, and a cell of ? is unknown.

{{ROLEROWS}} 
Clndrs,Volume,HpX,Model,origin,Lbs-,Acc+,Mpg+
8,304,193,70,1,4732,18.5,10
4,97,?,82,2,2130,24.6,40

Four x columns, three goals (lose weight, gain acceleration and mileage), one ignored column, one unknown cell.

ydist is 0 at a row that hits every goal and 1 at the worst possible row. Lower is better, everywhere in this system.

Options

{{OPTROWS}}

Written -Key val, space separated. A demo may poke a setting; it is put back afterwards, and every demo starts from a fresh seed.

Examples

./ezr_eg.py --treegrow a tree and print it
./ezr_eg.py -Stop 100 --holdout100 labels, not 50
./ezr_eg.py -File my.csv --treeyour own data
./ezr_eg.py --allevery demo; exit code counts the crashes
./rc sweep --holdout 8all of moot, 8 jobs

Exit status

Zero, or the number of demos that raised.

Requirements

Python 3.12 or newer, and nothing else. The library declares its vocabulary with type X = ... statements (PEP 695), which earlier versions cannot parse. There are zero runtime dependencies: no numpy, no pandas, no scikit-learn.

From a clone

git clone http://github.com/timm/ezr
cd ezr
./ezr_eg.py --h          # the demos and the settings
./ezr_eg.py --all        # run everything; exit code counts crashes

That is the whole install. ezr.py is a library with no __main__; ezr_eg.py is the command line.

Sample data

The demos default to a car-design dataset inside the moot repository. Clone it beside this one:

git clone http://github.com/timm/moot ~/gits/moot
# or let the run-commands file do it:
./rc ok

Point anywhere else with -File, which takes any csv whose header follows the role conventions on the Manual tab.

Optional tooling

gawkmake help, and the weave rule
pyccomake docs/ezr.html, the literate page
pandocthe .md to .html tutorials
pylint./rc lint ezr
a2ps, ps2pdfthe three-column printed listing

None is needed to run ezr. Each belongs to one target in the Makefile or one function in rc.

Known rough edges

Three things in the packaging do not currently match the code:

pip install ezrthe ezr and ezr-eg console scripts call main() with no arguments, but both take (args, funcs), so they raise on launch. Use a clone.
requires-pythondeclared as 3.10, but the type statements need 3.12.
./ezr.py --helpin the README; it exits silently because the library has no entry point. Use ./ezr_eg.py --h.
