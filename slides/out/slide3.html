3. Rare classes: read a third, find nine tenths

About 1% of these papers are a “yes”. Accuracy is useless — say “no” to everything and score 99%. Precision is useless too, and unavoidably so: at that base rate, catching nearly every hit means handing over a lot of misses. The question a reviewer actually asks is how much must I read?

min.py — complement naive bayes

def cnb(tbl, rows): # complement naive bayes: what a class is NOT like
  f, tot, all = {}, {}, 0
  for r in rows:
    k = r.raw[tbl.cols.klass.at]
    f.setdefault(k, {})
    for col in tbl.cols.x:
      v = r.raw[col.at]
      f[k][col.at] = f[k].get(col.at, 0) + v
      tot[col.at] = tot.get(col.at, 0) + v
  all, n = sum(tot.values()), len(tbl.cols.x)
  w = {}
  for k in f:
    den = all + n - sum(f[k].values()) + 1E-32
    w[k] = {a: -log((tot[a] + 1 - f[k].get(a, 0) + 1E-32) / den)
            for a in tot}      # no L1 norm here: it did not help, and
  return w                     # the rows it rescales are not the same

def cnbs(w, tbl, row, k): # how much this row looks like class K
  return sum(row.raw[a] * w[k].get(a, 0) for a in w[k])

Score a class by what it is not like. With 45 yes against 1659 no, the complement of “yes” is estimated from plenty of data; the class itself is not. Features are the 64 words with the most tf·idf.

read = the share of the held-out papers the model hands over. vs random = recall divided by that share: screening at random, reading 36% finds 36%. So Hall costs a third of the reading for 93% of the hits.

Spending more than ten labels does not help, and on Kitchenham it hurts (85% → 55% at 50 labels). The learner asks for whatever looks most like a yes, so the labelled set fills with yeses and the “no” side — the side complement NB actually estimates — starves.
